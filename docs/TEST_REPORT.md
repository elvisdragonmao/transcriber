# 測試與驗收報告（2026-10-19，emfox）

測試分成兩類，彼此不能互相替代：

- **自動化測試**：使用 mock worker（輸出格式和真實 worker 相同）加上真實的 ffmpeg，驗證上傳、佇列、狀態機、安全性與 Obsidian 歸檔邏輯。
- **真實模型驗收**：在 emfox 的兩張 GPU 上跑真實模型，透過和瀏覽器完全相同的 HTTP API 操作（`scripts/acceptance.mjs`），另外以 Playwright 實際操作 UI。

## 1. 自動化測試

| 套件 | 結果 | 指令 |
| --- | --- | --- |
| server（vitest） | **45 / 45 通過** | `pnpm --filter server test` |
| worker（pytest） | **8 / 8 通過** | `worker/.venv/bin/python -m pytest worker/tests` |
| TypeScript 型別檢查（server、web） | 通過 | `tsc --noEmit`、`tsc -b` |

server 測試涵蓋：

- **上傳**：
  - 需要登入。
  - 亂序、平行上傳；逐 chunk 做 SHA-256；以串流組合檔案。
  - complete 是冪等的。
  - chunk 大小 8／16／32 MiB，每個請求都小於 100 MB。
  - 續傳時伺服器回報已收到的 chunk；重送是冪等的；損壞的 chunk 回 422；缺塊時 complete 回 409，並保留 session 讓使用者補傳。
  - 不支援的格式回 415、過大回 413、磁碟不足回 507。
  - 帶路徑穿越的檔名被安全處理。
  - 同名檔案同時上傳時不會互相覆蓋。
- **轉錄流程**：
  - 每個階段都有真實進度與 waveform；TXT、MD、JSON、SRT、VTT 都能匯出。
  - 暫停時停在區段邊界，checkpoint 可以重用，恢復後 ASR 呼叫恰好 2 次。
  - 取消時不保留中間結果，之後重試會從頭開始。
  - 模擬當機重啟後，任務不會卡在 running。
  - OOM 會自動重試並留下紀錄。
  - 無法解碼的音訊會失敗，而且不重試。
  - 多個任務同時存在時，每張 GPU 同時只跑一個重型階段。
- **筆記與 Obsidian**：
  - 分類有把握時會歸進正確的專案資料夾，並建立雙向連結；frontmatter 不會被惡意值破壞；`<script>` 會被中和。
  - 惡意或不確定的分類只會寫進 Trans 範圍，其他資料夾逐 byte 不變；移出授權範圍的請求會被拒絕。
  - 使用者改過的筆記不會被覆蓋，改為另存 `v2`。
  - 轉錄完成後才產生筆記時，會建立獨立的筆記任務，原本的轉錄任務維持 100%。
  - 刪除原始錄音後逐字稿仍在；刪除整筆錄音時，Obsidian 檔案預設保留。
  - 講者改名會持久化並註冊聲紋，下一份錄音能自動辨識；人工修改文字後，原始模型輸出仍然保留。
  - Codex 未安裝的狀態會明確顯示。
- **單元測試**：
  - 講者歸屬依時間重疊計算、偵測講者切換、標示重疊與未確定段落。
  - 句子切分；聲紋「乾淨片段」會排除重疊語音。
  - 保守的聲紋比對（門檻、與第二名的差距、乾淨語音時長、一人不可同時對應兩位講者），以及依語言選擇門檻。
  - vault 路徑驗證（9 種攻擊形式）。
  - Claude adapter 的參數確實停用所有工具；prompt 只走 stdin、不經 shell；環境變數不外洩 token；工作目錄是空的；逾時與取消都能確實終止行程。
  - settings PATCH 只修改送出的區段，並驗證內容。

### 各階段耗時（秒）

| 階段 | 上課 81 分 | 辯論 53 分 | 中文 7 分 |
| --- | --- | --- | --- |
| prepare（ffmpeg 解碼 + speechnorm + waveform） | 11.4 | 5.5 | 1.0 |
| VAD（Silero ONNX，CPU） | 27.2 | 18.6 | 3.6 |
| ASR（Qwen3-ASR-1.7B，RTX 5060） | 413.5 | 686.7* | 44.4 |
| Forced Alignment（RTX 5060） | 15.2 | 7.4 | 4.2 |
| Diarization（Nemotron，RTX 3050，和上面平行） | 23.9 | 22.3 | 8.7 |
| Speaker ID（TitaNet，CPU） | 2.6 | 39.3* | 13.0 |
| 筆記（claude-sonnet-5-5，effort medium） | 55 | – | 40（UI） |

\* 辯論的 ASR 時間包含刻意的暫停，以及在佇列中等上課錄音使用 RTX 5060 的時間。兩份錄音是同時上傳的：上課錄音的 diarization 在 RTX 3050 上，和辯論錄音的 ASR 平行執行，RTX 5060 同時只跑一個 ASR。

ASR 實測約 **0.1 倍即時**（81 分錄音約 7 分鐘）。Forced alignment 每個字詞都有時間戳，對齊比例 100%。兩個模型同時常駐 RTX 5060 時，VRAM 約 5.7 GB（處理中峰值約 6.3 GB）。

## 3. 測試中發現並已修正的問題

1. `PATCH /api/settings` 會把沒送出的區段重設為預設值。這導致 GPU 對應被清空，worker 看不到任何 GPU。已改成只合併送出的區段，並加上回歸測試。
2. 不需要筆記時，Obsidian 匯出會在逐字稿產生之前就先跑完（依賴關係少了 `save`）。
3. 聲紋比對在 ASR 偵測出語言之前就決定了門檻。改為 identify 先做初步比對，merge 階段再依實際語言重新判斷。
4. 錄音音量小時（辯論錄音平均 -37 dB），VAD 只抓到一半的語音（213 秒對 diarization 的 432 秒）。改為在 VAD、ASR、對齊之前先用 ffmpeg `speechnorm` 正規化音量，之後 VAD 抓到 426 秒。
5. PyPI 的 NeMo 3.0.0 無法載入 Nemotron-3-Diarization（不支援 `rope`），改用模型卡列出的 Transformers 原生實作。
6. systemd 的 `EnvironmentFile` 不接受行尾註解。
7. 暫停後在排隊的階段只顯示「等待」，看不出已完成的部分；播放中的段落也遺失了標點。兩者都已修正 UI。
8. 取消時若不保留中間結果，任務會先被標為「已取消」，才非同步刪除檔案，造成狀態短暫不一致（測試偶爾失敗）。已改為刪除完成後才標記。
9. 前端靜態檔原本只為伺服器啟動時已存在的檔案建立路由，重新 build 後新檔名的 CSS／JS 會拿到 HTML。已改為請求時查檔，缺少的 `/assets/*` 回 404。
10. 命名講者的視窗每次輸入都會重新聚焦到關閉按鈕，導致打字中斷；按鈕沒有手型游標。都已修正。

- 中英混雜的長錄音沒有量化的 WER 測試。
- TitaNet 中文門檻（0.78）還沒有用真實資料校準。
- Codex CLI 未登入，所以沒有真實呼叫過。
